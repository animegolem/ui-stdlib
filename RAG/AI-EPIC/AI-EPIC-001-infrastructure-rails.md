# AI-EPIC-001-infrastructure-rails

## Problem Statement

A house UI standard library needs rails before components: a
registry whose admission cannot be bypassed, tokens whose colors
cannot be forged, lint whose diagnostics teach agents the law, a
build whose bytes reproduce, and a work-tracking shop with the
channel discipline the house already trusts. Without these, every
component wave would mint its own conventions — the exact debt the
library exists to prevent.

## Proposed Solution

One infrastructure wave delivering five rails as workspace
packages and a portable shop: @ui-stdlib/registry (two pinned
schemas, ONE admission API that the build also drinks from,
declaration-health and a11y-evidence admission, per-file SHA-256,
canonical-JSON content-addressed artifacts), @ui-stdlib/tokens
(one OKLCH source → --ui- custom properties, raw-color policy),
@ui-stdlib/lint (six ruled families, ESLint-v9 authority +
exact-pinned Oxlint parity receipt, triplet diagnostics), the
deterministic build, and the RAG/codex/carrier shop. Constitution:
RFC-0001 at the repo root.

## Paths Not Taken

Adopting @shadcn/lint directly (Tailwind substrate, no Solid);
remote-mutable registry as trust root; per-package parsers;
Rust/Go tooling for the rails (TS until the language lands);
cutting five separate tickets after the wave had already been
reviewed as one atomic commit — theater records refused.

## Operational Prediction

- Admission refuses every malformed manifest class in its fixture
  matrix with a field-precise error; no consumer ever parses
  manifests another way.
- Artifact bytes reproduce across cwd/locale/TZ/order on the same
  host; cross-OS stays unclaimed until CI runs those legs.
- Lint diagnostics carry contract + alternative + definition
  pointer on EVERY path (CLI included), and agents repair from
  them without human translation.
- The shop's tools cannot write outside the realpathed repo root —
  and the no-effect-before-admission law holds at every entry.
